## 🛠️ Forge parts and why not native

| Forge part | Why not native |
|---|---|
| `forge.mjs worktree` names | A VS Code worktree branch starts with `agents/`, and `create_session` has no branch name or base (microsoft/vscode#321685). Forge needs `repo.branchPattern`. |
| `git branch -m` in a New Worktree session | The same reason. After the rename, **Mark as Done** leaves the worktree (click-check 3), so close checks `git worktree list`. |
| `isolate_session` is not the default | It makes a native worktree, but Forge cannot set its folder or branch name. Click-check 2. |
| Gate approvals with SHA-256 manifests | A native plan approval does not cover a set of exact revisions. |
| Summary budget, `forge.mjs diff`, and the reading levels of older tickets | No native "changed since your last review" exists for wiki files, and no native check keeps a document short. |
| `forge.mjs canvas` and `canvas.html` | A native canvas comes from a canvas extension, runs only in a Copilot harness session, and cannot open without a session ([Canvases](https://code.visualstudio.com/docs/agents/run/canvases)). The docs give no file format for a canvas extension, and an enterprise policy can block one (`strictPluginOnlyCustomization`). The Markdown preview shows one static Mermaid diagram for each file. Forge needs the same page in each host and outside a session, so the page is one generated HTML file without a network request, opened in the integrated browser or in any browser. The first Forge canvas was a canvas extension, and Forge 5.0 removed it because the feature was not reliable. It is a view like `raw/board.md`: no manifest lists it. Forge 7.5 adds the tiers, the views, and the title strips to this page. The editor can fold a Markdown section, and the integrated browser can zoom a page, but no native feature knows which section the user must read for a gate (the integrated browser page, read on 2026-11-18). |
| **Send to agent** on a canvas of the live server | Until 7.0 the comments went back by copy and paste, and there was no server. The native **Add Element to Chat** with a comment exists only in the VS Code integrated browser. It sends one page element, without the ticket file and the section, and Claude Code and Copilot CLI have no such tool. A page from a `file://` link cannot give data to a session, and its clipboard permission is not sure (click-check 17). So the live server (`127.0.0.1` only, with the page token) takes the comments of the page at `POST /ticket/<folder>/send` and adds the message to `canvas-comments.md` in the ticket folder. Until Forge 10 a second server (an option of the canvas command) did this and printed the message to a background command, but a hook or a notice of a finished command is not a native way to wake a session on all three hosts, and two servers are more than one repository needs. Now the user tells the session `sent`. In Claude Code, the `UserPromptSubmit` hook adds the file to that message (`additionalContext`) and removes it. The other hosts have no prompt hook, so the session reads the file. The `file://` page with **Copy all** stays. The method follows Plannotator (a local server, a send button, the feedback as text). |
| Cold read (`agents` skill) | No host checks a document with a reader that does not have the session context. The check uses the native subagent tool, with a prompt that holds only the path of the document. It follows the Elephant-Goldfish pattern (Dave Rensin, Google Research), reduced to one read for each review revision. |
| `forge.mjs gate-open` (`scripts/lib/gate-open.mjs`) | The native plan review card of `/plan` approves a host plan. It has no hook, and it keeps no hash of a ticket document. So Forge builds the document set, writes the manifest with the SHA-256 of each file, and prints the form text. |
| The plan checks of `lint` (`scripts/lib/gate-checks.mjs`: `plan-path`, `plan-baseline`) | No native check of a plan document. A host cannot tell that a plan names a file that does not exist, or that a Check has no baseline run. |
| The plan review (`policy.planReview`, "Plan review" of the `agents` skill) | No native review of a plan by subagents. A custom agent file can set a `model`. Forge uses skill text, so that one text serves 3 hosts. Known gap: the reviewer model comes from `policy.adversarialReviewModel` and not from an agent file. |
| `policy.styleRules` | No native response style setting. The rules come from the sessionStart hook, and the key can turn them off. |
| `forge.mjs board`, `raw/board.md`, and the board page `raw/board.html` | The sessions list and the inbox mode show sessions, not ticket state from the wiki: the gates, the next step, and the waits. The Markdown preview of `board.md` has no filter, and its links open Markdown files. So Forge 7.2 adds the same data as one HTML page, with the same limits as the ticket canvas: one file, no network request, never a source. Forge removed its first canvas in 5.0: it was a Copilot canvas extension, and that feature was not reliable then. |
| `forge.mjs live`, `scripts/live-hook.mjs`, the live line of the board, and the Live panel of the canvas | Each host has a native view of its own sessions: the agent view of Claude Code (`claude agents`), the agent list of Orca, and the sessions list and the inbox mode of VS Code. None shows a session next to the gates, the next step, and the waits of its ticket. The transcript files of Claude Code are an internal format ([Sessions](https://code.claude.com/docs/en/sessions)), and a copy of a terminal has no subagent structure and needs a PTY module. So Forge 7.6 uses the native hooks: a background hook sends one small event to a server from the Node standard library on `127.0.0.1` only. The server is read-only for a session, keeps the events in memory, and starts only with `forge.mjs live`. Forge starts no session and has no terminal: a session runs in Orca, in a terminal, or in the Agents window, as before. |
| The session list (`scripts/lib/sessions.mjs`, `raw/sessions.jsonl`), **Resume** and **Copy command** on the board and the canvas, and `POST /resume` (`scripts/lib/harness.mjs`, `scripts/lib/terminal.mjs`) | Each harness has a native list of its sessions: the `/resume` picker and `claude --resume` of Claude Code, and `/resume` and `copilot --resume` of Copilot CLI. Each list has the sessions of one harness, and none has the ticket, the gates, or the next step of a session. The transcript files are an internal format, so Forge reads no transcript: the session hooks give the id, the folder, and the end. Forge has no terminal of its own: a PTY needs a native module, and a browser tab keeps keys such as Ctrl+W. So the button opens a tab of the terminal of the user with the native resume command. The user chose this on 2026-11-19, before a terminal in the page, a multiplexer that owns the sessions, and a chat box with headless runs. No host has a command that opens a terminal on each system, so `terminal.mjs` has one row for each terminal program. |
| Links between the pages: the ticket switcher, the previous and the next ticket, and `/board` and `/ticket/<folder>/` on the live server | [Manage sessions](https://code.visualstudio.com/docs/agents/run/sessions/manage-sessions) gives no link (URI) and no command that opens one session from outside (read on 2026-11-17), so a page cannot open the session of a ticket. The favorites, the history, and the tab list of the integrated browser know only pages that the user opened before, not the tickets of the wiki. So each page has relative links to the other pages, and `forge.mjs board` and `forge.mjs canvas <KEY>` write the pages that the links need. A served page of another ticket cannot send comments: the server stops and wakes only the session of its own ticket. A board card has a **Worktree** link (`vscode://file/<folder>`) as the nearest native step to the session (click-check 24). |
| The UI kit `scripts/lib/ui/` and [design-system.md](design-system.md) | No native feature: a local HTML page has no native component set, and the docs of the integrated browser name no theme variables for a page (read on 2026-11-20). The page must also be the same in Claude Code, in Copilot CLI, and in a plain browser. So the pages share their own tokens (color, type, space, shadow) as data, a light and a dark theme, and the same bar, switcher, help dialog, toast, and notice. One component for each part ends the copies that grew in each page (the review of 2026-11-19 found a part 2 to 7 times). No dependency: a micro library would be a vendored file for a few hundred lines. |
| The styleguide page (`forge.mjs styleguide`, `raw/styleguide.html`) | No native feature: VS Code has no preview of the tokens and the components of a local page. A page that shows each token, sprite, letter, and component in both themes is the one place to look at a change of the kit. It reads the same data as the pages, so it cannot drift. |
| The pixel sprites and the bitmap letters (`scripts/lib/ui/pixel.mjs`) | No native feature: the docs of the integrated browser name no icon set and no pixel font. A page loads nothing from a network, so a font file or an image file is not an option. The sprites and the 5 by 7 letters are data in the code, drawn as inline SVG with a hidden real text. The user chose own letters before an embedded open font. |
| `npm run shots` and the demo data (`tests/shots/run.mjs`, `tests/fixtures/demo.mjs`) | No native feature does this. The integrated browser page names an **Add Screenshot** step (read on 2026-11-20), but it is a step by hand for one page in VS Code. It is not a script, and it checks no console error, no content-policy violation, and no theme. The script shoots each page in 2 themes at 2 widths in headless Chromium, with invented data and its own live server. It is not part of `npm test`. |
| The stable page link, its key file, and `forge.mjs open --new-link` (`live-serve.mjs`, `open.mjs`) | No native feature keeps the token of a local server. A favorite of the integrated browser (the star in the address bar) keeps an address, but a new random token at each start made it fail. The key file is next to the state file, with a mode that only the user can read. The trade-off: the link is in the history of the browser and in the argument of the start command, so `--new-link` is the answer to a leak. A favorite after a restart is open (click-check 63). |
| The error pages (`errorPage()` in `ui/page.mjs`) | No native feature: a browser shows plain text for a plain answer, with no next step. The page has no script and its own content policy. A script or `curl` still gets plain text. |
| The notice that stays and the changed stamp of `/live` (`ui/banner.mjs`, `live-stamp.mjs`) | `workbench.browser.autoReloadOnFileChange` loads a local file again, but its name says file, and the docs do not say that it covers a page from `127.0.0.1`. A served page needs to say that the server stopped, or that the data changed, without a load that would drop a comment that is not saved. So the page asks, and it shows a notice with **Reload** and **Later**. |
| The tab icon with `img-src data:`, and the count in the title (`faviconUri()`, `pageHtml()`) | A browser shows a tab icon and a title, but the docs of the integrated browser name neither (read on 2026-11-20). The icon is a `data:` link, so it needs no file and no network. The content policy allows `img-src data:` only for it. Whether VS Code shows them is open (click-check 61). |
| `ownTurn` (`scripts/lib/own-turn.mjs`), the 600 character rule, and the closed ticket check of the prompt hook | The `UserPromptSubmit` hook has no input field for the origin of a turn (read on 2026-11-20), and Claude Code has no option to run it for typed prompts only. So the hook reads the first words of the text, which is a guess that can fail when Claude Code changes the text. The other 2 rules limit the harm. |
| The next strike strip (`nextStrike()` in `board.mjs`) | The sessions list and the inbox mode show sessions, not the gates, the next step, and the waits of a ticket. One strip that names the one next step is a view of the board data. It is not part of `board --json`. |
| The spark on a new approval (`ui/gates.mjs`) | No native feature tells a user that a gate changed since the last visit of a page. The script keeps the statuses in the storage of the page, and one CSS animation (0.6 s, 4 steps) plays only with no reduced-motion setting. It is the first part to cut when the scope is too large. |
| The wiki page (`scripts/lib/wiki.mjs`, `scripts/lib/wiki-page.mjs`, `raw/wiki.html`) | The [Markdown preview](https://code.visualstudio.com/docs/languages/markdown) shows one file inside the VS Code window, and **Find All References** lists the links to a header in the editor (read on 2026-11-18). The board and the canvas are browser pages that also run with Claude Code, Copilot CLI, and Orca. So Forge writes one page with each wiki page, the uses of each page, and the closed tickets, in the same design system. **Open the file** on a page still opens the Markdown file in the editor. |
| The Mermaid file `vendor/mermaid/mermaid.tiny.js` and `scripts/lib/mermaid.mjs` | The Markdown preview of VS Code draws no page outside the VS Code window (see the row above), and a browser has no Mermaid function of its own. So the plugin holds one file of the package `@mermaid-js/tiny` 12.3.0 (MIT, 2.7 MB), with its hash in the code and in a test. The wiki page and the ticket canvas load it from the folder `raw/` or from their own server, and only when the page has a Mermaid block. The user chose this build on 2026-11-18, before the full build (5.3 MB) and before a drawer of Forge for flowcharts only. |
| `forge.mjs open`, and a live server for each repository | The [plugin reference](https://code.claude.com/docs/en/plugins-reference) of Claude Code (read on 2026-11-19) gives a plugin a `bin/` folder, but its files are on the `PATH` of the Bash tool of the agent only, and claude.ai does not install a plugin that has this folder. No host gives a plugin a command for the terminal of the user, and no host shows the tickets and the wiki of a repository as pages. So `open` is a command of `forge.mjs`: it starts the server as a process of its own, and a second run gives the same links. One server for each repository keeps the pages and the sessions of two repositories apart. |
| The Forge folder `../<repo>.forge`, its launcher (`scripts/lib/launcher.mjs`), and `forge.mjs init` and `move` | No host gives a plugin a folder for the data of one repository that the user and each host share: `${CLAUDE_PLUGIN_DATA}` of Claude Code is one folder for a plugin and a user, in the Claude folder (plugin reference, read on 2026-11-19). `${CLAUDE_PLUGIN_ROOT}` "changes when the plugin updates", so a fixed command with the plugin path stops to work at each update. The wiki is a subfolder with its own git repository, so `raw/` and `archive/` need no `.gitignore` line to stay local. |
