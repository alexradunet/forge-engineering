## 🛠️ Forge parts and why not native

| Forge part | Why not native |
|---|---|
| `forge.mjs board` and `raw/board.md` (shown as a text table by the `board` skill) | No host shows ticket state from the wiki: the gates, the next step, and the waits. The native session views (`claude agents`, and the `/resume` pickers) show sessions only. So Forge reads the README frontmatter of each ticket, writes the plain file `raw/board.md`, and prints `board --json`. The skill answers with a text table in the chat. Forge 0.1.0 has no page, no server, and no browser view. |
| `forge.mjs worktree` names | Claude Code names a worktree folder `.claude/worktrees/<name>/` and its branch `worktree-<name>`, and `worktree.baseRef` accepts only `"fresh"` or `"head"`, not a branch name ([Worktrees](https://code.claude.com/docs/en/worktrees.md), read on 2026-11-26). The docs name no setting for a branch pattern. Forge needs `repo.branchPattern` and the folder `<repo>.worktrees/<key>-<slug>`, so it makes the worktree with `git worktree add`, and `EnterWorktree` with a path moves a Claude Code session there. Copilot CLI has `/new worktree` (CLI command reference, read on 2026-11-26): no rule for the branch name was read. Corrected on 2026-11-26: Claude Code has a `WorktreeCreate` hook ("Replaces default git behavior", no matcher, its stdout is the worktree path), so a hook could set the folder and the branch there. Forge does not use it yet (open list in "Known gaps"). Copilot CLI has no such hook in the docs that were read. |
| `forge.mjs board --all` | No host shows the tickets of more than one repository. Each Forge folder is next to its repository, so Forge reads the sibling folders. It writes no file, so it never writes into the `raw/` of another repository. |
| `forge.mjs statusline` and its shim | The status line is native, but its text is a command that the user gives. A plugin cannot set it, and `${CLAUDE_PLUGIN_ROOT}` changes at each update, so the settings name a shim in `CLAUDE_PLUGIN_DATA`, and the session start hook refreshes the shim. Copilot CLI has no status line. The install and a write of Claude Code to the settings file at the same time can lose one write; the install runs only after a yes, in an idle moment. |
| `host.notify` and `host.resume` | Host verbs only: they name the native `PushNotification` tool and the native `--resume`. Forge stores no session id. |
| Gate approvals with SHA-256 manifests | A native plan approval does not cover a set of exact revisions. |
| Summary budget, the diff of `gate-open`, and the reading levels of older tickets | No native "changed since your last review" exists for wiki files, and no native check keeps a document short. |
| Cold read (`agents` skill) | No host checks a document with a reader that does not have the session context. The check uses the native subagent tool, with a prompt that holds only the path of the document. It follows the Elephant-Goldfish pattern (Dave Rensin, Google Research), reduced to one read for each review revision. |
| `forge.mjs gate-open` (`scripts/lib/gate-open.mjs`) | The native plan review card of `/plan` approves a host plan. It has no hook, and it keeps no hash of a ticket document. So Forge builds the document set, writes the manifest with the SHA-256 of each file, and prints the form text. Corrected on 2026-11-26: a `PreToolUse` hook can match `ExitPlanMode` (hooks page: "`AskUserQuestion` and `ExitPlanMode` need `updatedInput` paired with `"allow"`"). That hook still has no hash of a ticket document, and it does not cover Copilot CLI, so the manifest stays. A hook on `ExitPlanMode` is on the open list. |
| The plan checks of `lint` (`scripts/lib/gate-checks.mjs`: `plan-path`, `plan-baseline`) | No native check of a plan document. A host cannot tell that a plan names a file that does not exist, or that a Check has no baseline run. |
| The plan review (`policy.planReview`, "Plan review" of the `agents` skill) | No native review of a plan by subagents. A custom agent file can set a `model`. Forge uses skill text, so that one text serves both hosts. Known gap: the reviewer model comes from `policy.adversarialReviewModel` and not from an agent file. Corrected on 2026-11-26: a plugin agent file can set `model` and `effort` (Claude Code plugin components page: the supported fields include `model` and `effort`). A plugin agent file for the reviewer is on the open list. |
| `repo.changeName: none` | A protected branch of the repository host stops each direct push, also a push of the user. Forge only gives the steps, and the gate guard checks a push from the ticket worktree. |
| `policy.styleRules` | No native response style setting. The rules come from the sessionStart hook, and the key can turn them off. |
| `ownTurn` (`scripts/lib/own-turn.mjs`), the 600 character rule, and the closed ticket check of the prompt hook | The `UserPromptSubmit` hook has no input field for the origin of a turn (read on 2026-11-20), and Claude Code has no option to run it for typed prompts only. So the hook reads the first words of the text, which is a guess that can fail when Claude Code changes the text. The other 2 rules limit the harm. |
| `forge.mjs local-key` (`nextLocalKey()` in `tickets.mjs`) | A host has no ticket id. Forge 14.0.0: the key is what the user types, and `L-<n>` is the key when the user gives none. The `L-<n>` comes from a counter file in `raw/`, and the folder, the branch, and the session title use it as each other key. |
| The setup presets (the team size step of `forge-setup`) | Claude Code has `userConfig` in `.claude-plugin/plugin.json`: a value for each user and each plugin, kept in `settings.json` ([Plugin manifest reference](https://code.claude.com/docs/en/plugins/manifest-reference.md), read on 2026-11-26). Forge has no `.claude-plugin/plugin.json`, its policy values belong to a wiki and so to a repository, and both hosts must give the same result. The [CLI plugins page](https://docs.github.com/copilot/concepts/agents/copilot-cli/about-cli-plugins) of Copilot (read on 2026-11-26) names no preset and no value that the user chooses at install time. So the setup skill asks and writes the policy values to `policy.md` with `forge.mjs config set`. No code reads a preset name. |
| The Forge folder `../<repo>.forge`, and `forge.mjs init` and `move` | No host gives a plugin a folder for the data of one repository that the user and each host share: `${CLAUDE_PLUGIN_DATA}` of Claude Code is one folder for a plugin and a user, in the Claude folder (plugin reference, read on 2026-11-19). `${CLAUDE_PLUGIN_ROOT}` "changes when the plugin updates", so a fixed command with the plugin path stops to work at each update. So the Forge folder is next to the repository. The wiki is a subfolder with its own git repository, so `raw/` and `archive/` need no `.gitignore` line to stay local. |
| Rules in the `sessionStart` hook context, not in `com.github.copilot/rules/` | Claude Code does not load a `CLAUDE.md` at the plugin root as context: instructions that load must be in a skill ([Plugin manifest reference](https://code.claude.com/docs/en/plugins/manifest-reference.md), read on 2026-11-26).
